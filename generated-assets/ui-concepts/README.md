# 北漂 · 多房间网站 UI 概念

> 归档说明：B 方案已被选定并实现，见项目根目录 README。下文保留最初选型时的方案说明；“尚未实现”等描述仅代表当时状态。当前首页按后续要求不再显示“空间总览”入口。

这三张是用于选择设计方向的电脑端概念图，并未修改或部署现有网站。图中的按钮与布局表达交互意图，不代表新功能已经实现。其他房间仅标注“待录入”，不预设真实入住顺序、日期、地址或租金。“北漂”为概念中的暂用站名，可替换。

## A · 居住档案（推荐）

暖白底、宋体标题、克制的深绿入口，像一本私人建筑摄影档案。真实照片占主导，左侧提供房间名称和入口，底部是可扩展的房间目录。亲切而不煽情，既能容纳细节资料，也适合长期增加房间。

- 图片：A-editorial-archive.png
- 适合：有照片、模型以及不同居住阶段，想保留日常感和浏览舒适度。
- 后续增加房间：目录追加条目；按实际居住顺序或名称排列，真实日期补齐后再展示，首页仍只突出一间。
- 手机：目录改为抽屉，房间照片和入口上下排；不强制横向浏览。

## B · 居住时间线

全屏房间影像，深色时间序列退到下方，选择一间就像翻到一段居住记忆。进入漫游的过渡最自然，画面感也最强。时间线目前只表达房间次序，不编造年份。

- 图片：B-cinematic-timeline.png
- 适合：希望首先获得沉浸与氛围，房间数量不多、少量资料即可。
- 后续增加房间：底部序列可滚动，同时保留目录入口，避免越来越难找。
- 手机：用紧凑上下切换或房间抽屉，不靠细小时间轴触点操作。

## C · 房间索引

固定房间目录与空间总览、实景照片并置，像一个建筑展览目录。更理性、清晰，突出“这些真实房间已经被保存成模型”这件事。

- 图片：C-spatial-index.png
- 适合：房间数量逐步增多，经常比较布局，愿意把空间和照片作为同等重要的资料。
- 图中的轴测房间是概念示意，并非实测平面或当前模型的渲染结果；落地时必须使用实际 Blender 模型，保留已经认可的布局和瓷砖地面。
- 手机：目录收起，总览与照片分为两个清晰的切换项。

## 共同交互原则

首页负责选房间；进入“自由探索”后让界面退场，仅保留轻量返回、总览/复位等必要入口。沉浸模式隐藏目录和页面装饰，触屏移动与升降键沿用已认可布局。所有入口支持键盘和触控，图标要有可理解标签；动画只帮助房间之间的连续过渡，不增加加载负担。

建议先以 A 作为整体视觉基调；若更偏爱进入房间的临场感，可选择 B。C 的索引方式适合将来房间较多时采用。

## 制作记录

使用 ui-ux-pro-max 进行整体视觉方向检索；参考其精简排版、清晰层次和触控原则，未照搬营销转化模板。使用内置 imagegen 逐张生成，主参考为用户提供的真实房间照片。生成提示词保存在 prompts.json。三张图已目视检查：中文核心文字清晰、主体一致，未出现虚构日期/租金/地址。
